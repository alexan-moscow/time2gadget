# BRIEF.md — Мастер-бриф проекта

Это канонический входной бриф проекта — аналог `.stitch/PROMPT.md` в проекте КЛЮЧ24. Источник истины о продуктовом замысле и правилах работы. Изменяется редко; текущий прогресс/статусы — в `ROADMAP.md`, архитектурные решения — в `ARCHITECTURE.md`/`DECISIONS.md`, точный UI-контракт — в `UI-CONTRACT.md`.

---

## 1. РОЛЬ

Ты — разработчик компактного Windows-desktop приложения на C# / .NET 8 / WPF. Работай по фазам (см. §20 ROADMAP), не смешивай архитектурные слои, не вводи технологии сверх ТЗ без явного запроса.

---

## 2. ПРОДУКТ

**Название:** Таймер (рабочее название проекта — «Кулинарный гаджет-таймер», кодовое имя решения — `Time2Gadget`).

Компактный современный таймер-гаджет для Windows 10, постоянно находящийся на рабочем столе, для быстрого запуска обратного отсчёта (кухня и не только — общее применение).

Ключевые качества:
- современный минималистичный вид (Fluent / лёгкий glassmorphism), НЕ стиль старых Windows Gadgets;
- главный элемент — круговой таймер;
- окно без стандартной рамки Windows, скруглённые углы, перетаскивание мышью;
- лёгкое и быстро запускающееся приложение, без Electron/embedded browser.

---

## 3. ТЕХНОЛОГИИ

- C#
- .NET 8
- WPF

Явно НЕ использовать: Electron, встроенный браузер, тяжёлые UI-фреймворки поверх WPF.

Предусмотреть возможность portable-сборки (запуск без полноценного инсталлятора).

---

## 4. ОСНОВНОЙ ИНТЕРФЕЙС

Размер окна (Normal-режим): примерно 300×300–320×320 px.

Центр:
- крупное цифровое значение оставшегося времени (`23:47`);
- под ним подпись состояния (`ОСТАЛОСЬ` / `ГОТОВ`);
- вокруг центра — тонкий круговой индикатор прогресса (отдельный элемент, не сектора).

Вокруг — **единое кольцо из 8 кликабельных секторов** (НЕ отдельные круглые кнопки):

| Сектор | Значение |
|---|---|
| 1 | 5 мин |
| 2 | 10 мин |
| 3 | 15 мин |
| 4 | 20 мин |
| 5 | 30 мин |
| 6 | 45 мин |
| 7 | 60 мин |
| 8 | 90 мин |

Между секторами — тонкие разделители. Сектора занимают всё пространство кольца (равные углы, 360°/8 = 45° каждый), без крупных пустых промежутков.

Внутри сектора — число + подпись (`5` / `МИН`, либо компактно `5 мин`).

---

## 5. СОСТОЯНИЯ СЕКТОРА

- **Обычное** — тёмная полупрозрачная поверхность, тонкая граница, светлый текст.
- **Hover** — плавная подсветка при наведении.
- **Выбранный** — яркая холодная синяя подсветка (единственный основной акцент-цвет проекта). Не использовать кислотные цвета.
- **После запуска** — выбранный сектор и/или внутреннее кольцо прогресса становятся индикатором хода отсчёта; прогресс уменьшается плавно (анимация без рывков).

---

## 6. ЦЕНТРАЛЬНАЯ ОБЛАСТЬ

Центр — НЕ кнопка выбора времени.

```
23:47
ОСТАЛОСЬ
```

Обновление каждую секунду во время работы. Если таймер не запущен — показывать выбранное время и статус `ГОТОВ`:

```
30:00
ГОТОВ
```

---

## 7. УПРАВЛЕНИЕ (нижний ряд, 3 круглые кнопки)

- **Левая — Mute.** Вкл/выкл звук окончания. Состояние (иконка перечёркнутого динамика) сохраняется между запусками.
- **Центральная — Start/Pause.** До запуска `▶`, во время работы `Ⅱ`, после окончания снова `▶`. Визуально самая заметная кнопка.
- **Правая — Reset `↻`.** Сбрасывает текущий отсчёт и возвращает выбранное время.

---

## 8. ЛОГИКА ВЫБОРА ВРЕМЕНИ

- Клик по сектору выбирает время; если таймер не запущен — устанавливает его.
- Если таймер уже запущен — клик по сектору НЕ меняет время автоматически.
- Допустимое удобное поведение: первый клик — выбор, повторный клик по уже выбранному значению — запуск. Это поведение должно быть легко заменяемо архитектурно (инкапсулировано, не захардкожено в UI-коде).

---

## 9. КОЛЕСО МЫШИ

Над центральной областью: колесо вверх — `+1 мин`, вниз — `−1 мин`. Не допускать отрицательного времени. Разумный верхний предел — 24 часа.

---

## 10. ГОРЯЧИЕ КЛАВИШИ

- `Space` — Start/Pause
- `R` — Reset
- `Esc` — остановить/сбросить текущий отсчёт

На первом этапе — локальные для окна. Архитектура должна допускать последующее добавление глобальных горячих клавиш без переписывания ядра.

---

## 11. ЗАВЕРШЕНИЕ ТАЙМЕРА

При достижении `00:00`:
- отсчёт останавливается;
- если звук включён — сигнал;
- визуальное сообщение о завершении (плавная пульсация круга/центра, временная смена акцента на красный/оранжевый);
- Start снова доступен.

Не делать агрессивное системное уведомление. Windows Toast Notification — желательная, но необязательная для MVP опция.

---

## 12. ALWAYS ON TOP

По умолчанию включено. Отключаемо через контекстное меню/настройки.

---

## 13. СИСТЕМНЫЙ ТРЕЙ

Закрытие окна — сворачивание в трей, не завершение процесса. Меню трея:
- Показать таймер
- Start / Pause
- Reset
- Always on Top
- Запускать вместе с Windows
- Выход

---

## 14. АВТОЗАПУСК

Настройка «Запускать вместе с Windows» — штатный механизм автозапуска Windows (реестр `Run`), без сторонних менеджеров.

---

## 15. ВНЕШНИЙ ВИД

Ориентир — современный компактный desktop-widget, не стандартное окно WPF.

Использовать: тёмный фон, слегка прозрачные поверхности, скруглённые углы, мягкие тени, тонкие границы, синий акцент, плавные hover/progress-анимации, крупную читаемую типографику.

Цветовая схема (ориентир, точные токены — `DESIGN-SYSTEM.md`):
- фон — очень тёмный сине-серый;
- основной текст — белый;
- вторичный текст — серо-голубой;
- акцент — современный яркий синий;
- ошибка/завершение — красный/оранжевый.

НЕ использовать: градиенты в стиле старых Windows-программ, массивные рамки, стандартные квадратные WPF-кнопки, перегруженные настройки, декоративные элементы без функционального смысла.

---

## 16. КОМПАКТНЫЙ РЕЖИМ

Второй режим отображения — Compact, ~180–220 px. Показывает: время, небольшой прогресс-круг, Start/Pause, Mute, Reset. Сектора выбора времени можно скрывать. Переключение — через контекстное меню.

---

## 17. ПЕРЕМЕЩЕНИЕ ОКНА

Без стандартной рамки — перетаскивание мышью за свободную область (верх окна либо центр, когда он не занят другим действием), не мешая работе кнопок/секторов.

---

## 18. СОХРАНЕНИЕ НАСТРОЕК

Между запусками сохранять: последний выбранный таймер, состояние звука, Always on Top, компактный/обычный режим, положение окна, настройку автозапуска.

Простой локальный конфигурационный файл (JSON), без базы данных.

---

## 19. АРХИТЕКТУРА (обязательные принципы)

Разделение на логические компоненты: Timer engine, Timer state, UI, Settings, Tray, Sound notification, Keyboard input. Не смешивать логику в `MainWindow.xaml.cs`. MVVM или лёгкий MVVM-подобный подход.

**Критично про таймер:** не привязывать отсчёт к количеству срабатываний UI-таймера. Использовать точное время начала/окончания (`DateTime`/`Stopwatch`), UI обновлять отдельно от механизма отсчёта — чтобы задержки UI не накапливали ошибку. После паузы — корректный пересчёт оставшегося времени.

Полный технический контракт — `ARCHITECTURE.md`.
